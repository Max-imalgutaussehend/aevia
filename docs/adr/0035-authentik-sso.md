# ADR-0035: Authentik as the single login for operator tools

Status: accepted (2026-10-20)

## Context
Argo CD, Grafana, Prometheus, FreeLLMAPI, n8n, Kuma and ntfy sit behind Cloudflare Access (email one-time PIN per app) and
have their own logins. Authentik ran but was connected to nothing.

## Decision
- Authentik is configured by a blueprint (`gitops/base/platform/authentik-blueprint.yaml`, mounted via the chart):
  group `operator`, the bootstrap user `akadmin` (email = operator email) as its member, and three OIDC applications
  restricted to that group: Cloudflare Access, Grafana, Argo CD.
- Cloudflare Access gets Authentik as an additional OIDC login method (tofu, `cloudflare_zero_trust_access_identity_provider`).
  The email PIN stays enabled as break-glass; apps do not restrict `allowed_idps`.
- Grafana (`auth.generic_oauth`) and Argo CD (`oidc.config`) log in with Authentik; group `operator` maps to Admin. The
  local `admin` accounts remain as break-glass.
- Client secrets are random, SOPS-encrypted (`authentik-env`, `grafana-oauth`, `argocd-oidc`), generated by
  `scripts/gen-k8s-secrets.py`. Tofu reads the Cloudflare one from `authentik-env` at apply time (`TF_VAR_authentik_cloudflare_secret`).

## Consequences
- One login (password plus passkey or TOTP, registered in Authentik) covers every gated host.
- If Authentik is down, Cloudflare Access still accepts the email PIN, and Grafana/Argo CD still accept the local admin.
- Argo CD is installed by hand with Helm, so `configs.cm`/`configs.rbac` in `gitops/platform/argocd-values.yaml` were also patched live.
- n8n, Kuma, ntfy and Prometheus have no OIDC; they rely on the Cloudflare login.
